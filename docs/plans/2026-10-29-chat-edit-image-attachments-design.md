# 海报设计对话改图附件设计

## 目标

海报设计工作台的对话改图输入框支持上传图片和 `Ctrl+V` 粘贴剪贴板图片。上传后的图片以 asset id 随改图请求提交，后端转换为可访问图片 URL，并同时传给接口 `/images/edits` 与 Agent 两条改图链路。

## 交互

- 输入框左侧增加图片选择按钮，最多附加 5 张。
- 对话区域监听粘贴事件；剪贴板包含图片时阻止默认文本粘贴，并把图片转为文件上传。
- 上传期间显示缩略图占位；上传完成后显示缩略图、文件名和删除按钮。
- 发送改图时保留文字要求；消息历史显示本轮图片缩略图。
- 上传或提交失败时在对话区域显示错误；提交失败不清空已上传附件。

## 数据流

1. 前端调用现有 `POST /api/assets` 上传文件，取得 asset id 和预览 URL。
2. `POST /api/whole-image/tasks/{id}/edits` 新增 `reference_asset_ids`，最多 5 个并去重。
3. 后端校验 asset 存在，把 id 写入 `edit.reference_asset_ids`，并在用户消息中保存图片附件。
4. `run_edit` 读取附件 asset：
   - 接口链路在原始内容图、当前海报之后追加附件图，并在提示词中声明其角色。
   - Agent 链路把当前海报和附件图都转换为公开图片 URL，按顺序拼进 Agent input。
5. 失败重试继续使用 `edit.reference_asset_ids`，不丢失附件。

## 约束与错误处理

- 仅接受图片文件；前端过滤非图片，后端仍由现有上传接口验证图片内容。
- 单轮最多 5 张附件；后端 Pydantic 再校验并去重。
- 不存在的 asset id 在任务被 claim 前返回 422。
- 图片 URL 获取失败时对应改图链路失败，沿用现有 partial/failed 结果处理。
- 当前海报仍是编辑底图；附件图是本轮用户提供的参考图，不替代当前海报。

## 验证

- 后端测试覆盖请求字段规范化、附件持久化、接口链路图片顺序、Agent input URL 和模型输入快照。
- 前端执行 `npm run build` 和 `npm run lint`，不新增测试依赖。
