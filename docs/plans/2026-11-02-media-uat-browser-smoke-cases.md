## 1. 验收方式与判定规则

用户明确要求：**由执行 agent 使用 Codex 内置浏览器，在真实 UAT 页面实际操作并验收。** 单元测试、Playwright 测试脚本、curl／HTTP 请求或截图首页都不能替代这些页面用例。

- 本会话的内置浏览器入口是 mcp__cua_repl，目标为 in-app browser（iab）。执行 agent 先按工具要求初始化，阅读返回的浏览器操作文档，再打开真实页面。
- 必须通过实际页面完成选择、输入、文件上传、点击提交、查看任务、切换版本和点击下载。禁止直接 POST 创建任务、修改 Mongo 状态或注入假结果来冒充页面操作成功。
- Shell、数据库、日志和图片元信息检查只用于准备测试文件、受控运维及核实页面操作确实落库／落文件，不能替代页面中的业务动作。
- 不以外部 Chrome、browser-act 或只运行 Playwright 脚本冒充“Codex 内置浏览器已验收”。若执行会话没有内置浏览器能力，应报告环境阻塞，不宣告页面验收通过。
- 页面按钮名称参考当前代码；新增的 AM 启动入口和资源库界面尚待实施。测试时先观察真实页面，在记录中写下实际菜单／按钮名称；不得把不存在的按钮当作已操作。
- 每条用例状态从“未执行”开始。只有全部必需步骤有实际结果和证据才改为“通过”；失败要修复并重跑该用例，条件缺失标“阻塞”。
- 测试仅在指定测试商家进行。截图保存到证据目录；视觉核对使用缩略图或独立短上下文，遵守 AGENTS.md，不把大图／base64 放进长会话。
