# 部分或全部设计元素拆层

1. 确认用户指定组。例：“把右上标语和橙色牛肉标签做成能拖动的元素”只拆这两组，不自动拆主标题或Logo。未提到的继续固定。
   用户明确说“所有元素拆开”时，先盘点标题/文字组、Logo、笔刷衬底、贴纸、插画、独立装饰、分隔线、照片及底图，建立每组的id/来源/初始位置/可调或固定清单。说明合组粒度；背景可作为最底固定底图，但不能将未拆的Logo和分隔线藏在固定层里后声称全拆。
2. 每组由Agent调用一次Core AI原生generate_image透明编辑，直接以原海报或已有前景为参考，不先生成不需要的中间模板。文案以原图为准；用户的转述不自动作为改字要求。将该组文字、承载笔刷底色、必要关联图标放在同一PNG。需要更细的文字/底色分层时再按明确要求处理。
3. 另生成去除这些组的固定层；若已有真正分层源文件则复用。旧整张透明模板不能藏在下方，否则移动后仍有旧字。抽出一块矩形裁图也不能作为语义分离；矩形会把相邻图案或摄影一起带走。
   若全部设计已成为独立组且没有需固定的内容，直接创建原画布同尺寸全透明RGBA固定层，不为一张空图额外生图。仅拆部分组时仍保留其余固定设计。无照片的海报允许slots为空，不制造假照片占位。
4. 检查艺术字移走后的背面：补完品牌底色、被挡住的固定设计；完整不透明背景放最底层，不要用透明去字底板填空。原照仍保持原始素材，不用模型补画照片去凑可调区域。
5. 合成顺序为：**完整不透明底图 → 每张原照的独立窗口 → 去字后的固定层 → 各独立艺术字贴纸**。完整底图必须实际绘入canvas及PNG，不能只设CSS背景色来隐藏棋盘格。
6. 将manifest设为 `mode: elements`，写明 `element_request`，提供真实 `background` 和 `elements`。有照片时HTML支持照片/元素两种选择模式，避免文字遮住照片就无法选中照片；纯元素海报只显示元素控件。所有元素沿用 `kind: art` 的内部实现，支持移动、缩放、旋转、隐藏和单独下载透明PNG，不限于艺术字。
7. 验收全画布：隐藏全部艺术字、单独隐藏每组、移开全部照片、切换固定层预览、导出PNG，都不能出现透明像素；独立贴纸下载仍透明。检查底层没有被拆走的文字残片，也没有把这些文字重新生在底图里。

模型拆层可能改变字形、底色边缘和角标外形。明确说明是可调整的试验/重建结果；不要承诺原像素或字体完全一致。艺术字是位图，并非可任意输入文字的HTML字体。

照片优先使用用户完整原照，按独立窗口取景。有照片但没有原照时，只能使用原海报中真实可见的面板裁图并标明来源，不能恢复已被文字遮挡的像素，也不能把模型重画照片称为保真拆层。菜品需要作为可跨窗口自由移动的主体时，应另用菜品模式的干净底图和自身alpha，不能承诺本窗口构建器会自动完成。

普通流程约每组1次生成，固定层和底图只在确有需要时生成；真实源图层、合格底图和空固定层可以复用，不为凑次数调用模型。各组、固定层和底图的prompt及来源分别记录。
