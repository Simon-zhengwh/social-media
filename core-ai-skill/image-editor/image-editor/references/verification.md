# 验收

## 整张摄影背景

- 使用模型原生透明设计前景，不以本地抠图替代。核对整张授权摄影场景已移除，文字/Logo/实心底/边框都完整，字间与笔刷孔洞无旧摄影。
- 使用background模式的一个全画布窗口，完整新背景原照字节不变，固定层沿用已验模型RGBA。generation记录须绑定原生前景PNG；photo_core严格透明、比例检查仍执行。
- 字形和边缘可能经过模型重建，视觉对照原稿；浏览器检查只证明背景取景、换图和PNG导出，不证明视觉还原。

## 两阶段改字

- 新字贴纸逐字检查通过后，第二阶段才引用原海报及这张已验贴纸。两阶段记录分别绑定输入、输出SHA，PENDING/FAIL不得写成PASS。
- 最终PNG确由模型输出，尺寸与原稿一致且完全不透明。检查旧字残片、新字位置/比例/衬底，以及未指定摄影和设计是否漂移；package_text_edit.py只打包，不本地贴回。
- report会记录outside_edit_changed_pixels；非0须查明是否可接受，不把人工PASS记录或哈希一致当作像素保真认证。改字不强制HTML或浏览器测试。

## 菜品模式先验空底图和抠图

生成前先用--prepare-assets集中检查环境、全部输入、范围叠图和抠图；仅范围检查可用--prepare-layout。生成后集中查看--prepare-background的对照页，模型背景与最终空背景的区别用于判断是否可以本地修范围后复用。removal_scope若提供，须被有效修补区完整覆盖。

- 菜品模式不使用下面的透明photo_core规则。完整无菜品底图必须完全不透明，隐藏/移开全部菜品后，逐段检查全部旧盘沿、食物、影子和补背景过渡，不能仅凭几个采样点通过。
- 每张OpenCV抠图检查完整外轮廓、灰边、孔洞、脱离主体的杂点和原照截边。RGB须逐像素等于完整原照；分割只改alpha。原照本来缺失的盘沿说明限制，不生成补齐。
- 先用--prepare-background导出最终空背景，review同时绑定背景输入与最终合成像素。背景、每张抠图分别保存真实视觉结论和哈希，残留/杂点先记录FAIL并修正，修补区或保护区调整后重新验收。构建器核对证据一致性，视觉检查独立完成。
- 新菜品自由移动，不能被旧菜品轮廓或旧窗口裁切。验证1张和多张菜品独立调整、隐藏/移动后的完整背景、单独透明PNG、整张全不透明PNG及本地添加透明菜品。照片窗口/元素模式继续按下文验收。
- 每个菜品默认去背景，并可独立切换保留完整原照背景。切换前后位置/缩放/旋转/显隐相同，选中点击区域随图片alpha变化，其他菜品选择不变。验证两种版本的单独PNG和当前选择的整图导出；复制继承但切换互不影响。单独导入且无原照的透明PNG须明确禁用保留背景选项，刷新恢复默认去背景。

## 照片窗口/元素模式先验素材

- 核对海报/每张原照/每个窗口的映射；检查图片EXIF、尺寸、alpha、哈希。
- 先验替换范围：只换菜品时，海报木桌、台面、香料和其他背景仍应保留，不能因其属于摄影内容就挖空。单独标记窗口外的摄影背景保护区并检查，不能只证明Logo/文字保留。
- 验证HTML内嵌的是完整原照，未擅自抠主体、去灰底或替换成主体alpha图。灰底在局部窗口内随原照出现属于用户自行调整的取景内容；把它铺到整个海报或新增标题背景窗口属于越界修改。
- 透明模板的照片内核应真正透明，不只是文件标为RGBA。隐藏全部原照查字间、笔刷孔洞、白框两边和窗口凹口；移除旧食物及对应容器的全部可见部分。
- photo_core须从原海报独立标注，覆盖食物和容器/盘沿；全为alpha=0才通过。保护区不得与旧照片内核重叠；失败不缩小内核、不改成宽松alpha阈值。
- 检查长宽比并拒绝超过0.2%的偏差；照片模式使用原海报尺寸。不能把contain产生的透明侧边当作正常尺寸映射。
- 照片模式逐像素比较最终固定层与映射后的模型模板：RGBA必须一致，不得按窗口裁模板或从原稿恢复像素。另查所有应露出原照的区域（模板alpha<240，包含半透明边缘）都有照片窗口接收，避免出现透明窄缝。原稿只作设计与范围对照，不再以窗口外零变化证明正确。protected_regions在photos中只检查模型保留情况。
- 保留固定设计的完整实心底，不能抠掉白字、黑字或贴纸内部图案。模型输出需逐元素核对文案、位置、笔触与边缘；允许标注重建差异，不冒充像素一致。
- 不用新照片遮住旧照残片。OCR不能可靠验收全部艺术字；OCR结果与视觉结论分别记录。

模板质量失败应保留证据并停止成品构建。不得选一张已知存在侧边透明、盘边残留等缺陷的失败稿继续套HTML，再用“交互通过”替代素材验收。用户明确要求查看失败证据时可展示失败PNG与报告，但不改写成合格结论。

## HTML和导出

运行 `python scripts/check_editor.py editor.html --out browser-checks.json`。已有本地浏览器时可传 `--browser`；没有Playwright或浏览器则记录未执行，不能声称浏览器通过。不要为测试偷偷连接用户已登录浏览器或上传素材。

已有chromium路径优先传--browser；依赖和浏览器在生图前按preparation.json检查。读图只有描述模板、没有实际图像/描述时，不计作视觉验收，也不重复同一路径读取。

至少验证：照片数量不固定（1张和多张），每张拖动、滚轮/滑块缩放、方向键微调、重置、本地换图及无效图回退，放大原照不串窗。预览与导出共用绘制逻辑；导出精确画布尺寸，选中框、棋盘格均不导出。

默认照片模式可隐藏照片检查透明前景，不必拆元素。元素模式另检查每组可选、可拖、可旋转、可隐藏、独立下载；透明像素不拦截点击，照片模式仍能选中被艺术字遮住的原照。纯元素海报无照片控件且仍能操作、导出；“全部拆层”逐项核对清单，Logo、插画或分隔线未拆时必须明确说明。

元素模式必须扫描**整个canvas和实际下载的PNG**：隐藏全部艺术字、移开全部照片、固定背景预览，非不透明像素数应为0。仅看CSS颜色或少数采样点不算通过。独立贴纸下载的原生alpha应仍透明。

## 交付记录

交付新目录，不覆盖旧版HTML、输入或已验收PNG。附以下内容：

- 可独立打开的 `editor.html`，说明拖动/缩放后点击下载PNG。
- 两阶段改字改为主交付模型原生 `final.png`，附新字透明贴纸、两阶段记录/审核、原稿、edit-region、manifest和技术报告。
- 菜品模式附完整空背景、各原照、抠图PNG和分割mask。照片模式附透明前景、完整原照和窗口mask。明确拆元素时再附每组PNG、不透明底图和去字固定层。
- 可复跑manifest、完整模型提示词/调用记录、技术report、浏览器结果和实际视觉结论。
